# BS Profiler 3.1

BS Profiler 3.1 строит характеристику личности по короткому видео русской речи: пять черт Big Five, тип MBTI
(запись тех же шкал в другой нотации), эмоции, голос, мимику и речь. За один анализ работает одна выбранная модель —
`AMLAI 1.0` (собственная, по рецепту MM-PSYCHE) или `OCEAN-AI` (веса MuPTA). Результат — страница, PDF-отчёт и запись
в журнале; исходные файлы задания по прямой ссылке не отдаются.

Система не ставит психологических диагнозов: это кажущаяся личность по первому впечатлению, а тип MBTI — запись
четырёх шкал Big Five в другой нотации, а не результат опросника.

История версий — в [CHANGELOG.md](CHANGELOG.md).

## Быстрый старт

На уже настроенной машине (venv установлен, веса на месте, Ollama запущена в Windows):

```bash
bash bs3-studio/scripts/run_web3.sh                 # веб: http://localhost:7880 (лог ~/bs3_data/logs/web.log)
pkill -f "bin/bs3 we[b]"                             # остановить веб

bash bs3-studio/scripts/run_preview.sh ~/bs3_data/web_jobs/<задание>   # предпросмотр готового задания на :7882
pkill -f "ui_previe[w].py"                           # остановить предпросмотр

~/bs/venv/bin/python bs3-studio/tests/run.py        # тесты (только стандартная библиотека)
```

Без установки пакета: `PYTHONPATH=bs3-studio ~/bs/venv/bin/python -m bs3.cli web --port 7880`.

## Требования

- Windows 11 с WSL2 (Ubuntu-24.04). Обе версии проекта (2.0 на :7870 и 3.1 на :7880) могут работать одновременно.
- Видеокарта NVIDIA с поддержкой CUDA в WSL. Проверено на RTX 5090 Laptop, 24 ГБ.
- Около 15 ГБ на диске под модели (веса AMLAI 1.0 и OCEAN-AI, модели Hugging Face, модель Ollama).
- Ollama работает в Windows и доступна из WSL (см. «Установка с нуля»).

## Установка с нуля

1. **Ollama в Windows.** Установить Ollama, задать `OLLAMA_HOST=0.0.0.0`, разрешить входящие TCP 11434 из подсети WSL
   (правило брандмауэра Windows), затем `ollama pull qwen2.5vl:7b` — это зрительная модель описаний поведения и подписей
   кадров и переводчик описаний.
2. **Пакеты Ubuntu:** `sudo apt install python3.12-venv ffmpeg poppler-utils fonts-dejavu-core git`. `ffmpeg` нужен для
   ffprobe и нарезки отрезков, `poppler-utils` — для проверки PDF в тестах, `fonts-dejavu-core` — шрифт PDF-отчёта.
3. **Клонировать репозиторий** и поставить локальную метку, на которую опирается тест изоляции:
   `git tag v3-base 1d9fe30` (последний коммит до появления каркаса 3.0).
4. **Общий venv** (используется совместно с 2.0, обновлять его нельзя): создать через `bs/scripts/setup_wsl.sh`, затем
   `~/bs/venv/bin/pip install -r bs3-studio/requirements-wsl.txt` и отдельно
   `~/bs/venv/bin/pip install --no-deps oceanai==1.0.0a48` (без зависимостей, иначе тянет конфликтующие версии).
   Проверенные версии перечислены в `requirements-wsl.txt`.
5. **Установить пакет** в режиме разработки, без зависимостей (чтобы общий venv не тянул обновления):
   `~/bs/venv/bin/pip install --no-deps -e ./bs3-studio`. Повторять после смены версии; проверка — `~/bs/venv/bin/bs3 --version`.
6. **Веса AMLAI 1.0** из релиза v1.0 разложить в `~/bs/mm_runs_seeds/seed{1,2,3,4,42}/best.pt` (пять сидов, усредняются;
   путь задаёт `settings.MM_CHECKPOINTS`).
7. **Веса OCEAN-AI** скачиваются автоматически при первом анализе этой моделью в `~/bs/models`
   (`settings.OCEANAI_MODELS_DIR`; каталог создаёт `backend_oceanai.py`).
8. **Модели Hugging Face** скачиваются при первом запуске (суммарно около 5,5 ГБ) в кэш HF (`~/.cache/huggingface`):
   Whisper `openai/whisper-large-v3-turbo` для транскрипта (самая крупная из них) и энкодеры признаков анализаторов.
9. **Проверить Ollama из WSL:** `curl http://<шлюз WSL>:11434/api/tags` должен ответить. Если localhost из WSL не
   достаёт до Ollama, задать адрес явно: `export BS3_OLLAMA_URL=http://<шлюз WSL>:11434` (иначе адрес ищется
   автоматически — сначала localhost, потом шлюз WSL по умолчанию).
10. **Прогнать тесты** (`~/bs/venv/bin/python bs3-studio/tests/run.py`), затем запустить веб
    (`bash bs3-studio/scripts/run_web3.sh`).

## Запуск

- **Веб-страница:** `bash bs3-studio/scripts/run_web3.sh [ПОРТ]` (по умолчанию 7880). Загрузка ролика, выбор модели,
  характеристика, PDF. Остановить: `pkill -f "bin/bs3 we[b]"`.
- **Предпросмотр готового задания** (проверка вёрстки без анализа на видеокарте):
  `bash bs3-studio/scripts/run_preview.sh [ПАПКА_ЗАДАНИЯ] [ПОРТ]` (по умолчанию — новейшее задание, порт 7882).
  Папка задания должна лежать в `~/bs3_data/web_jobs`. Остановить: `pkill -f "ui_previe[w].py"`.
- **Командная строка** (`~/bs/venv/bin/bs3 …`, остановить — Ctrl-C):
  - `bs3 web [--port 7880] [--host 0.0.0.0] [--work-dir DIR]` — та же страница, что и через скрипт;
  - `bs3 infer ВИДЕО [ВИДЕО …] [--out отчёт.json] [--backend mm|oceanai] [--segment 20]` — оценки одного или
    нескольких роликов; по умолчанию модель AMLAI 1.0 (`--backend mm`) и распознавание речи включено; объяснений
    `infer` не считает;
  - `bs3 explain ВИДЕО --out ПАПКА` — только AMLAI 1.0: оценки, вклад модальностей, вклад кадров и слов, ключевые кадры.

Веб-сервер 3.1 запускается только вручную. Автозапуск не включён; служба 2.0 (`bigfive.service`) остаётся остановленной
и отключённой.

## Где что лежит

- `~/bs3_data/web_jobs` — по одной папке на анализ со страницы (значение по умолчанию `settings.JOBS_DIR`, устройство
  папки — в [docs/result_json.md](docs/result_json.md));
- `~/bs3_data/logs` — журнал (`journal.txt`) и лог веб-сервера (`web.log`);
- `~/bs3_data/gradio_tmp` — временная папка Gradio (`GRADIO_TEMP_DIR`), только через неё сервер и отдаёт файлы;
- `~/bs` — общие с 2.0 ресурсы только на чтение: venv (`~/bs/venv`), веса OCEAN-AI (`~/bs/models`), чекпоинты
  AMLAI 1.0 (`~/bs/mm_runs_seeds`);
- `~/.cache/huggingface` — кэш моделей Hugging Face; кэш Ollama — на стороне Windows.

Каталог `BS3_DATA_DIR` переносит все папки `~/bs3_data` разом. Пул обработанных роликов из 3.1 убран: если от прежних
запусков остался каталог `~/bs3_data/pool`, он больше не нужен и его можно удалить вручную.

## Настройки

Все настройки собраны в `bs3/settings.py` (пути, модели, Ollama, веб-сервер, нарезка длинных роликов). Полная таблица
настроек, переменных окружения и того, на что влияет каждая, — в [docs/config.md](docs/config.md).

## Проверки перед коммитом

Пять проверок; идентификаторы образцов передаются в командной строке и в репозиторий не попадают. Все — только на
процессоре, видеокарта не нужна. Запускать из общего venv (`~/bs/venv/bin/python`).

1. **Тесты** — `bs3-studio/tests/run.py` (около 324 тестов, ~60–70 с; только стандартная библиотека, модели не
   загружаются).
2. **Изоляция от 2.0** — `bs3-studio/tests/run.py test_isolation.py` (~4 с): ничего из `bs2` не импортируется, рабочие
   папки под `~/bs3_data`, имя и версия — из `bs3/__init__.py`.
3. **Контраст палитры** — `bs3-studio/scripts/check_palette.py` (доли секунды): цвета «Ключевых фактов» читаются в
   светлой и тёмной теме и на печати.
4. **Пересборка образцов** — `bs3-studio/scripts/rerender_samples.py A=~/bs2_data/web_jobs/<образец A>
   B=~/bs2_data/web_jobs/<образец B>` (~8 с): два эталонных задания 2.0 (у A 18 отрезков, у B 33) переносятся в
   `~/bs3_data/web_jobs` и рендерятся без изменения содержимого. Идентификаторы образцов задаются здесь и не хранятся в
   репозитории.
5. **Эталон поведения** — `bs3-studio/scripts/compare_baseline.py compare` (~40 с): страница, PDF, строки журнала и
   устройство страницы всех заданий совпадают со снимком под `~/bs3_data/refactor_baseline` (пересобрать снимок —
   `… capture`).

Проверки задают `PYTHONWARNINGS=ignore GRADIO_ANALYTICS_ENABLED=False`. При импорте сторонних пакетов (gradio, oceanai,
mediapipe и других) могут появляться их собственные предупреждения — SyntaxWarning об экранировании и предупреждения об
устаревании; на результат они не влияют.

## Старые задания

- **Задания 2.0** переносятся в `~/bs3_data/web_jobs` скриптом `scripts/import_job.py` (сама папка 2.0 остаётся
  нетронутой; 3.1 в неё не пишет). После этого их открывает предпросмотр.
- **Задания 3.0 и ранние 3.1** открываются как есть: `scores.clean_view` берёт модель, записанную в задании, и
  показывает только её оценки; сохранённые старые разделы `mbti` не показываются, тип пересчитывается при показе.
- **Тип MBTI старому заданию** можно дописать скриптом `scripts/add_mbti.py`, если его там нет.

Какая это версия, определяется по `model.selected` (есть — 3.1), иначе по `model.product` (3.0), иначе 2.0; поле
`model.version` для этого не используется (см. docs/result_json.md).

## Приватность и публикация

- **Где лежат данные.** Всё под `~/bs3_data` (по умолчанию): папки заданий, журнал, временная папка Gradio. Личные
  данные (имена в названиях файлов, транскрипты) хранятся локально и в репозиторий не попадают.
- **Что отдаёт сервер.** Только из своей временной папки Gradio. Из папок заданий (`web_jobs`) по прямой ссылке ничего
  не скачать: ключевые кадры страница показывает как data-URI, графики — через srcdoc, а PDF отдаётся из временной папки
  Gradio (`web.app.pdf_for_download`). `allowed_paths` не задаётся.
- **Имена заданий** непредсказуемы: `ГГГГММДД_ЧЧММСС_<8 hex>`. «Сохранено в» и блок result.json на странице показывают
  только имя, без пути на сервере.
- **Что пишет журнал** (`~/bs3_data/logs/journal.txt`, один текстовый файл, только дозапись): вход на страницу, старт
  анализа (файл и выбранная модель), результат (оценки модели, тип MBTI, короткий абзац характеристики и папку задания),
  ошибку или остановку. Кто зашёл — из заголовков обратного прокси: `X-Forwarded-For` (адрес) и `X-Remote-User` (логин
  из basic-auth Caddy); при локальном доступе — «локально».
- **Что хранит папка задания.** Остаются исходное видео (`input.*`, нужно для повторного анализа и как запасной источник
  для PDF) и результат (`result.json`, у AMLAI 1.0 также `explain/`, графики и PDF). Отрезки (`segments/`) удаляются
  сразу после успешной записи `result.json`; `BS3_KEEP_SEGMENTS=1` их сохраняет для отладки. Неудачный анализ папки не
  оставляет вовсе; `BS3_KEEP_FAILED_JOBS=1` оставляет её для отладки. Старые папки (с отрезками от прежних версий и
  недоделанные) вычищает `scripts/clean_jobs.py` — по умолчанию это сухой прогон (показывает, что удалит и сколько
  освободит), удаляет только с `--apply`, работает лишь внутри рабочей папки и не трогает `input.*`, `result.json`,
  `explain/`, графики и PDF.
- **Временная папка Gradio** чистится сама: `delete_cache=(3600, 79200)` удаляет старые копии раз в час, а `run_web3.sh`
  и шаблон службы при старте удаляют из неё файлы старше суток.
- **Очередь и минимальная длина.** Анализ идёт по одному за раз (одна видеокарта): второй пользователь сразу видит
  «В очереди», его ролик обработается автоматически, когда освободится очередь. Ролик короче 2 секунд отклоняется сразу
  (и на странице, и в командной строке), как и файл без видео или без звука.
- **Полоса темпа речи** — одна на весь проект: 100…160 слов в минуту (`scores.TEMPO_BAND`). По ней считаются и цвет
  карточки, и слова «медленный / спокойный / быстрый», так что число на карточке не бывает окрашено одним образом, а
  названо другим.
- **Публикация.** Сервер слушает `0.0.0.0` и рассчитан на работу за обратным прокси Caddy с basic-auth. Флаг `--share`
  (публичная ссылка gradio.live) с реальными данными использовать нельзя.

## Частые проблемы

- **Ollama не видна из WSL.** Проверить `OLLAMA_HOST=0.0.0.0` в Windows, правило брандмауэра на TCP 11434 и адрес
  шлюза WSL. Задать адрес явно: `export BS3_OLLAMA_URL=http://<шлюз WSL>:11434`.
- **Недостаточно памяти видеокарты.** Запускать один анализ за раз (сервер и так держит очередь на один); закрыть
  другие задачи на видеокарте; при переключении модели прежняя выгружается автоматически.
- **Порт занят.** Другой экземпляр уже слушает 7880/7882 — остановить его (`pkill -f "bin/bs3 we[b]"` или
  `pkill -f "ui_previe[w].py"`) либо запустить с другим портом.
- **Растёт `~/bs3_data/gradio_tmp`.** Обычно чистится сама (см. «Приватность и публикация»); при остатках после сбоя
  запустить `run_web3.sh` ещё раз или удалить старые файлы вручную.
- **Тест изоляции падает из-за метки `v3-base`.** Поставить её: `git tag v3-base 1d9fe30`.
- **Скрипт `.sh` не запускается (`\r`).** Файлы с окончаниями CRLF из Windows: `sed -i 's/\r$//' скрипт.sh`
  (в репозитории `.gitattributes` держит `.sh` в LF).

## Оговорки

Модели эмоций, голоса и выражений обучены на англоязычных корпусах и фотографиях: их выходы — сигналы о поведении на
видео, относительные и не откалиброванные для русскоязычных людей. Big Five — кажущаяся личность по первому
впечатлению; метка «собеседование» (есть только у AMLAI 1.0) — не рекомендация о найме. За один анализ работает одна
модель, и её результат — одно описание. Модели обучены на разных данных и работают на разных шкалах: OCEAN-AI (веса
MuPTA) обычно даёт 0.65–0.80 по O, C, E, A, AMLAI 1.0 — 0.3–0.45, поэтому по формуле с границей 0.5 первая чаще даёт
ENFJ или X на части осей, вторая — I, S, T, P или X. Если один ролик обработан обеими моделями, это два разных
описания, и напрямую сравнивать их не следует.
